# Synth

A physically modelled guitar (any layout from one to six strings, ukulele included)
plus basic keys and a basic drum kit, each with its own effect chain, mixed through a
channel strip, return buses and a limited master, behind one versioned note contract,
`mnx-sound/2`. It ships as two things from this repository:

- **The app**: a static web app, chain first: every part is a lane (instrument →
  effects) that runs into the mixer. Instruments, chains, the mix and whole sessions
  are configured and played here, and event logs and conformance fixtures are checked.
- **The headless library** (`@mnx-lab/synth`): the contract, the instrument host,
  the instruments and effect blocks, the AudioWorklet processor and the compiled DSP,
  with no UI. Other software (mnx-lab first) drives it and never configures it;
  sessions made in the app are handed over as rig 3.0.0 JSON.

This is the 0.2.0 line, a fresh start with no compatibility with earlier rigs, saved data or
0.1.0. It lives in mnx-lab as `synth/` (its own workspace and the `/synth/` shell), moved here
by [core-campaign-synth](../roadmap/complete/core-campaign-synth.md). The contract is
[docs/contract.md](docs/contract.md). The campaigns that built it (the instrument host and
chain campaigns, with their decisions and evidence logs) and the guitar-model research stay in
the guitar-faust repository, the read-only record of the synth's history.

## Run the app

```bash
npm -w @mnx-lab/synth start   # serves synth/web/ on http://localhost:8080
```

- **Chain**: one lane per part (guitar, ukulele, basic keys, basic kit). Add effects
  (drive, vibrato, tremolo, echo) with `+`, drag them to reorder or between lanes, and
  switch each On or Off (the signal passes unchanged and the tail rings out; then the
  effect costs nothing).
  Each lane runs into its channel strip (level, pan, mute, solo, room send); the Room
  return bus and the Master (volume, limiter ceiling) close the mix. Selecting any
  block opens its editor; on phones it opens as a sheet. Undo/redo, and A/B compare
  between the saved and the edited session.
- **Pieces**: the transport's Piece picker chooses what is played: short named pieces
  (a band groove, guitar strums, bends, legato and mutes, fingerpicking, sustain,
  dynamics, a recorded performance, a ukulele strum, keys with the pedal, a kit groove,
  a tempo change). It changes only the music: your parts play the lines for their
  instrument, and a line no part plays shows as a ghost lane with "Add part".
  **Session → Examples** loads a piece with the setup it was written for.
- **Inspect**: every diagnostic (including techniques lowered by `lower()`), an offline
  analysis of what you are hearing with note labels, an example's measured checks
  while it is unedited, and the contract's test fixtures.
- **Files**: sessions and single parts export and import as rig 3.0.0 (what plays, no
  music); "Export what I'm hearing" writes the session and its piece as one event log,
  which opens back like an example.

## Use the library

```bash
npm run build:lib    # → dist/lib (package @mnx-lab/synth)
```

```js
import {InstrumentHost,validateSetup} from '@mnx-lab/synth';
const host=await InstrumentHost.create(audioContext);host.connect();
await host.configure(setup);                       // parts, chains, room, master
await host.schedule({notes,controls,through});     // stream; upsert by note id
await host.cancel({from:audioContext.currentTime,silence:true});   // seek / stop
```

The stream says what is played and the setup what plays it: notes carry techniques and
optional chord `gesture`s (strum by stroke, roll by pitch), and the tempo is a
session-wide control (`{id, at, type:'tempo', bpm}`), which tempo-synced effects follow.

In Node, `import {render} from '@mnx-lab/synth/node'` renders offline with the
packaged assets. `@mnx-lab/synth/conformance` runs fixture expectations against
any renderer. Types ship with the package.

## Repository

| Path | What |
|---|---|
| `web/contract/` | `mnx-sound/2`: validators, `lower()`, capabilities, JSON schema, fixtures, conformance kit |
| `web/host/` | instrument host (chains, strips, buses, master), effect block catalogue, offline renderer, AudioWorklet processor and client, rig 3.0.0, instruments (`plucked`, `keys`, `kit`) |
| `web/app/`, `web/index.html` | the app |
| `web/model/`, `web/audio/` | Engine2 guitar engine and planning |
| `dsp/engine2/` | Engine2 guitar DSP (the plucked instrument) |
| `dsp/blocks/` | audio blocks: drive, vibrato, tremolo, echo, the room bus and the master limiter (3 ms look-ahead, soft knee) |
| `dsp/keys-basic.dsp`, `dsp/kit-basic.dsp` | basic keys and kit |
| `dsp/faust-toolchain.json` | pinned FAUST version and library files for every DSP build |
| `web/generated/`, `web/data/` | compiled DSP, published designs, the piece library (`web/data/pieces/`, generated by `scripts/build_pieces.mjs`) |

## Build

FAUST 2.81.10 with the pinned libraries is required only to rebuild DSP; every build
checks the pins.

```bash
npm run build:v2        # Engine2 guitar; must reproduce the published binary
npm run build:blocks    # effect blocks, room bus and master
npm run build:basic     # basic keys and kit
npm run build:lib       # headless library → dist/lib
npm run build:app       # deployable app → dist/app
```

## Test

```bash
npm test                # unit, host, conformance, library smoke (~2 min)
npm run verify:math-kernel  # WASM tanh = Math.tanh on all 2^32 float32 inputs (~30 s)
npm run test:app        # app flows in headless Chrome (needs npm start or STUDIO_URL)
npm run test:host-browser   # host in a real AudioWorklet ↔ Node, bit for bit
npm run benchmark:host  # performance budget (browser, Node, live)
```

Browser tests use Playwright from `PLAYWRIGHT_MODULE` with `CHROME_PATH`, in an isolated
profile. Determinism (Node ≡ worklet), batching and block-size invariance and the measured
conformance fixtures are the standing guarantees; deliberate sound changes are re-baselined
with listening sign-off (chain campaign, C3).
`npm test` runs its files concurrently (`node --test`), then the timing-based per-part
cost check on its own; per-design renders run in worker threads
(`TEST_WORKERS` caps them, `TEST_WORKERS=1` runs everything in one thread).
