## Evidence and method

The [pinned manifest](../converters/fixtures/musicxml-suite/manifest.json) supplies each original path, feature description, hash and suite revision. The [verifier](../harness/verify/musicxml-directions-assessment.py) derives IDs such as `31a-Directions/p01/m04/d02` and its child `/c01` from the XML's part, measure and direction order. It inventories **84 notes, 79 directions, 93 direction children and 101 lyric reference labels**. Source pitch, written value and per-note lyric text are compared with browser-imported MNX by part and measure. Both shells imported identical MNX. The verifier hashes every [retained document, observation, SVG and screenshot](../harness/fixtures/musicxml-directions-evidence/manifest.json) and checks selected imported fields and SVG ink behind the verdicts.

Chrome 153.0.8010.36 used a 1440×1000 viewport, staff scale 1 and density 2. Clefs and time signatures were set to **Show** and lyrics to **All verses** so the source's direction labels stayed visible. The `31a` score required three overlapping Workbench scroll tiles and two Studio tiles; all other complete scores fit one viewport. The observation JSON records the visible and scroll dimensions, no import/capture/render/console errors, and only `31a`'s source-located `ffz` warning. Studio's XML versions were made current/editable through Versions before capture; that is a render prerequisite, not an item 19 authoring or GP storage pass. No original declares known strings, so Tab/Both are inapplicable.

The first combined Workbench capture stalled before it wrote an observation for `31f`. A separate bounded Workbench run and a separate Studio run opened `31f` successfully. The original split run indexes and a consolidated index are retained under each shell's evidence directory; the `31f` verdict uses the successful captures. The last command verifies the committed copies. The official MusicXML [direction definition](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/direction/) says multiple child types follow one another visually. The [offset definition](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/offset/) measures in divisions and can shift a direction's appearance. [Metronome](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/metronome/) distinguishes printed beat units, metric relationships and parentheses. These semantics, and each original's manifest description, ground the findings below; no pixel-perfect spacing is demanded.

The `31c` dotted tempo marks are a useful positive control: the SVG contains the dot glyph for each surviving mark even when it is small in the screenshot. The `31b` end-of-bar hairpin is the opposite: its start/end object exists in imported MNX, but both complete SVGs have zero hairpin primitives. For `31f`, the raw newline remains in MNX and in the SVG text node, yet the browser paints one line because the renderer emits no line spans or equivalent whitespace treatment.
