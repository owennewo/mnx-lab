## Evidence and method

The [pinned manifest](../converters/fixtures/musicxml-suite/manifest.json) supplies each original path, description, SHA-256 and revision. The [source/import verifier](../harness/verify/musicxml-notehead-assessment.py) derives note, event and control IDs directly from the original XML, checks every source pitch, event grouping and written value against browser-imported MNX, and verifies the [retained capture hashes](../harness/fixtures/musicxml-notehead-evidence/manifest.json). The evidence includes each shell's imported MNX, observation JSON, complete Notation SVG and tiled PNGs. All four originals opened in each shell. Studio's XML versions were made current and editable through Versions; this is a rendering prerequisite, not an item 19 authoring or GP save pass.

Chrome 153.0.8010.36 ran at 1440×1000, device scale 1, staff scale 1 and density 2. Clefs and time signatures were set to **Show**. The first pass used the shells' default **Current verse** preference; the retained pass explicitly selected **All verses** through Settings before judging missing labels. `22a` needs three overlapping Workbench scroll tiles and two Studio tiles to cover all 32 bars; each other score fits one tile. No source declares known strings, so Tab/Both are inapplicable. Both shells imported identical MNX, with no console errors or projection exceptions.

Reproduce in an isolated worktree after `npm ci` and `npm run build`:

~~~sh
MUSICXML_CAPTURE_FILTER='^22[a-d]-' MUSICXML_CAPTURE_TIME_SIGNATURES=show MUSICXML_CAPTURE_LYRICS=all MUSICXML_CAPTURE_DIR=/tmp/mnx-musicxml-noteheads-workbench node harness/verify/musicxml-editor-capture.mjs
MUSICXML_CAPTURE_SHELL=studio MUSICXML_CAPTURE_FILTER='^22[a-d]-' MUSICXML_CAPTURE_TIME_SIGNATURES=show MUSICXML_CAPTURE_LYRICS=all MUSICXML_CAPTURE_DIR=/tmp/mnx-musicxml-noteheads-studio node harness/verify/musicxml-editor-capture.mjs
python3 harness/verify/musicxml-notehead-assessment.py
~~~

The capture commands write fresh observations to `/tmp`; the verifier checks committed evidence. Replace retained captures only after visual review and rehashing. The official [MusicXML notehead definition](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/notehead/) distinguishes shape, `filled` and parentheses; [notehead values](https://www.w3.org/2021/06/musicxml40/musicxml-reference/data-types/notehead-value/) include Aiken shapes, `none` and the directional arrows. [Slash-style spans](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/slash/) have start/stop and a stem choice. The [note attributes](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/note/) separate `print-object` from `print-lyric`, and [staff-lines](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/staff-lines/) permits zero.

The [published MNX note](../spec/mnx-schema.json) has no general head-shape or parenthesis field. Event lyrics do have numbered lines, so `22c`'s line-2/3 loss is an importer issue. Published `rest.staffPosition` can represent the final `22d` rest height; [item 25](../roadmap/proposed/core-musicxml-rest-fidelity.md) already proposes that mapping. The `22b` zero-line warning is [item 22](../roadmap/complete/core-musicxml-render-gaps.md)'s completed containment, not full variable-line support. `22d` also requests the incompatible common-time symbol on 6/4; the existing meter warning and numeric 6/4 display are separate from its notehead verdicts.
