## Evidence and method

The [pinned manifest](../converters/fixtures/musicxml-suite/manifest.json) supplies each original path, hash and description. The [source verifier](../harness/verify/musicxml-spanners-assessment.py) derives stable IDs from part, measure, direction/note, notation wrapper and marker order, for example \`33g-Slur-ChordedNotes/p01/m01/n02/nt01/slur01\`. It records each source marker, paired endpoint, offset, pitch/voice/chord context and the imported measure's spanner objects. Its pitch oracle confirms **164/164 pitched notes** across these eleven files in both imported documents, including nested tuplets and grace groups. Workbench and Studio imported identical MNX for each original. Pitch survival does not make a missing spanner correct.

[Retained evidence](../harness/fixtures/musicxml-spanners-evidence/manifest.json) hashes all 22 imported documents, observations, complete SVGs and PNGs. Chrome 153.0.8010.36 used 1440×1000, staff scale 1 and density 2. **Clefs and meters were set to Show, lyrics to All verses.** Each score fit one complete tile; each observation records the actual viewer scroll dimensions, display options, render diagnostics, warnings and editable binding state. Neither source declares known strings, so Tab/Both are inapplicable. Studio's XML version was made current and editable through Versions as a render prerequisite. That is no item 19 authoring or GP save pass.

Reproduce after \`npm ci\` and \`npm run build\`:

~~~sh
MUSICXML_CAPTURE_FILTER='^33[a-k]-' MUSICXML_CAPTURE_TIME_SIGNATURES=show MUSICXML_CAPTURE_LYRICS=all MUSICXML_CAPTURE_DIR=/tmp/mnx-spanners-workbench node harness/verify/musicxml-editor-capture.mjs
MUSICXML_CAPTURE_SHELL=studio MUSICXML_CAPTURE_FILTER='^33[a-k]-' MUSICXML_CAPTURE_TIME_SIGNATURES=show MUSICXML_CAPTURE_LYRICS=all MUSICXML_CAPTURE_DIR=/tmp/mnx-spanners-studio node harness/verify/musicxml-editor-capture.mjs
python3 harness/verify/musicxml-spanners-assessment.py
~~~

The last command verifies the committed report and retained-file hashes without rewriting them. The source is the visual oracle, with the official MusicXML definitions clarifying [octave-shift sizes and pitch semantics](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/octave-shift/), [direction offsets](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/offset/), [default wavy glissando](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/glissando/), and [let-ring ties](https://www.w3.org/2021/06/musicxml40/musicxml-reference/data-types/tied-type/). Pixel-perfect spacing is not required; correct identity, ends, attachment and visible style are.
