**Implementation loop. ## Evidence and method

The [pinned manifest](../converters/fixtures/musicxml-suite/manifest.json) gives each original's path, hash and description. `32e-Fermatas` has no description; its seven explicit source shapes and the official [fermata definition](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/fermata/) supply that inventory. The [verifier](../harness/verify/musicxml-notations-assessment.py) derives IDs such as `32c-MultipleNotationChildren/p01/m01/n01/nt01/articulations01/staccato01` from source order, including separate `<notations>` and `<articulations>` wrappers. Every source note or rest, pitch, written value and lyric text is checked against imported MNX by part and measure. It additionally checks `32e-Arpeggios-Cross` voice and staff assignments. Workbench and Studio imported identical MNX.

The [retained evidence](../harness/fixtures/musicxml-notations-evidence/manifest.json) hashes the imported documents, browser observations, SVGs and PNGs. Chrome 153.0.8010.36 used 1440×1000, staff scale 1 and density 2. **Clefs and meters were set to Show, lyrics to All verses.** `32a` needed four overlapping Workbench and three Studio scroll tiles; each other score fit one tile. The verifier checks bottom-tile coverage, one SVG per score, no browser/import/render errors, exact display settings and SVG mark-class counts. The only converter warning is `32a` measure 23's `sfffz` other-dynamic. Studio's original XML version was made current and editable through Versions before capture; that is a render prerequisite, not a GP storage or authoring pass. None of these files declares tuned strings, so Tab/Both are inapplicable; a solitary `<string>5</string>` technical mark in `32a` supplies no tuning.

Reproduce after `npm ci` and `npm run build`:

~~~sh
MUSICXML_CAPTURE_FILTER='^32' MUSICXML_CAPTURE_TIME_SIGNATURES=show MUSICXML_CAPTURE_LYRICS=all MUSICXML_CAPTURE_DIR=/tmp/mnx-notations-workbench node harness/verify/musicxml-editor-capture.mjs
MUSICXML_CAPTURE_SHELL=studio MUSICXML_CAPTURE_FILTER='^32' MUSICXML_CAPTURE_TIME_SIGNATURES=show MUSICXML_CAPTURE_LYRICS=all MUSICXML_CAPTURE_DIR=/tmp/mnx-notations-studio node harness/verify/musicxml-editor-capture.mjs
python3 harness/verify/musicxml-notations-assessment.py
~~~

The verifier checks committed evidence and report bytes without regenerating them. The official MusicXML [arpeggiate](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/arpeggiate/) definition says its number groups simultaneous chords together or separately; [non-arpeggiate](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/non-arpeggiate/) marks bracket endpoints. [Harmonic](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/harmonic/) distinguishes base, touching and sounding pitches, and [bend](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/bend/) distinguishes bends, releases and pre-bends. The source and these definitions ground the findings; exact engraver spacing is not treated as a pixel golden.

## Source → imported MNX → visible Notation

Each finding below holds in **both** desktop shells; the machine report has an individual source variant and shell row with cause and evidence path. All 175 source note/rest entries keep their order, pitch and written value; all 166 lyric reference labels survive. A lyric that spells “arpeggio”, “fermata”, “staccato” or “fingering” is a reference caption below the staff, **not the musical mark**.

The machine report counts one score-structure positive control per fixture in each shell. Those six controls account for twelve of the 24 correct rows; they do not turn the missing notation marks into passes. The `32a` SVG's 16 harmonic symbols, two hammer/pull curves, one positive bend curve and one pre-bend agree with the MNX inspection. Its zero fermata, arpeggio and articulation nodes, and the same zeroes in `32c`–`32e`, prevent lyric labels or intact noteheads from masking the gaps.
