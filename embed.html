Embedding the MNX Lab viewer

This page mocks someone else's site — a third-party docs page that drops the MNX Lab component in with one script tag. Everything inside the rounded frames below is the component; everything outside is the host's own (deliberately different) design. 

<!-- one script tag; no server, no framework, assets resolve relative to the component -->
<script type="module" src="https://mnx-lab.totai.uk/mnx-editor-app.js"></script>

<mnx-editor-app mode="viewer" scenario="spec/accidentals" json></mnx-editor-app>

Viewer mode

mode="viewer" renders one document: score on paper, the view toggle when the part declares _x.tab, and the document pane a click away. Note selection and JSON cross-highlighting work exactly as in the full app.

⌄ The component is sized by its container, not the viewport — drag the dashed right edge.

Below ~420px the chrome compacts: the id and version line drop, controls tighten, the brand reduces to the mark.

Guitar: notation + tab inline in prose

The proving-ground case — a lesson page interleaving text with small live examples. Chrome stays quiet so the music reads like a figure, with provenance one glance away.

controls="false" — a bare figure: all six open strings.

A 330px sidebar slot.

Gallery mode

mode="gallery" embeds the whole library — rail, facets, score, document pane — inside whatever box the host gives it. Same component, one attribute.

Theming

The component is themed entirely through CSS custom properties on the element — the host never reaches inside. The score paper stays paper in both themes; the document, not the chrome, is the constant. 

mnx-editor-app { --mnx-accent: #9C4F33; } /* or theme="dark" */

theme="dark" — chrome inverts, paper doesn't.

--mnx-accent: oxide — selection, chips, and controls follow.
