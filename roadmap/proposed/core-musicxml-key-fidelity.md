# MusicXML key fidelity — draw full fifth counts and surface lost key detail

> **Status: proposed, 2026-09-24.** MusicXML campaign item 28, from the bounded [13-series render assessment](../../docs/musicxml-key-assessment.md). Serves the implementation loop. [Campaign contract](../inprogress/core-campaign-musicxml.md).

## Agreement

1. **Oracle:** the seven pinned `13a–13f` MusicXML originals, manifest descriptions/hashes, official key and cancellation definitions, source-to-imported-MNX comparison and retained current Workbench/Studio captures in the [assessment](../../docs/musicxml-key-assessment.md). The original sources and independent reference semantics judge visible key ink; an import or round trip alone does not.
2. **MNX verdict:** published `key.fifths` is an integer and already carries ±11; no extension is needed for the traditional extreme count. Published `key` has no alteration list, octave choices, explicit cancel value/location, rhythmic position or hide flag. This item diagnoses those losses. Full support requires a separate spec-loop carrier proposal (topic: key-signature-detail); no new standard or vendor key is invented here.
3. **Dependencies:** no new runtime dependency or notation library.
4. **Matrix:** converter support cells and independent-oracle observations are regenerated by their owners after converter changes, never upgraded from screenshots.
5. **Losslessness:** ±8…±11 key values produce distinct, complete signature ink without moving note pitches. Every carrier-dependent loss below is source-located and explicit until a representation is agreed. Any later engine/model change re-earns primitives and registers verification debt under repository rules; no hand-written scenario verification.

## P1: complete traditional fifths above seven

`13a` retains all 46 source integers in MNX. Its 16 extreme bars have absolute fifths 8–11 but the notation engine limits the key-glyph list to seven while spacing prices the full count. Both shells display visually identical seven-sign keys for distinct values.

Acceptance: lay out and draw complete, distinct accidental runs for each ±8…±11 value using a stated engraving reference and exact source-value assertions. Compare all 23 fifth counts in both original-file shells, including major/minor pairs, zero-key cancellation and system breaks. Preserve the 30 already-correct -7…+7 bars and unchanged note pitches. Use a minimal authored MNX probe to isolate rendering from import, and check primitives and browser captures.

## P1: diagnose key details that cannot survive MNX

`13c` loses two nontraditional signatures with eight explicit alterations and five octave placements; `13d` loses seven alterations including fractional values. `13e-Cancel` loses four cancel values/locations; `13e-MidMeasure-Change` loses three later in-bar keys; `13f` drops `print-object="no"` while retaining the effective -4 fifths. All currently import without key-specific warnings, and the visible output is incomplete or misleading.

Acceptance for this bounded stage: emit precise source-located warnings for each unsupported nontraditional list, key-octave, cancellation value/location, midmeasure declaration and hidden-key display request. Warnings distinguish a missing signature from a preserved effective fifths value; they do not claim visual support. Keep unrelated notes and supported key changes intact. Recapture the seven originals through both shells and assert the warnings, imported MNX and score projection. Plan full import, engraving, editing and export only after the key-signature-detail carrier decision, including defaults and per-staff scope.

## Deduplication and deferrals

[Item 22](../complete/core-musicxml-render-gaps.md) owns fractional note-pitch diagnostics and already completed ordinary clef/meter fixes; those are not key-signature support. [Item 23](../complete/core-musicxml-write-gaps.md) owns Studio's untitled-version promotion. The `13a` and `13b` mode values disappear semantically but request no extra key glyph; assess their create/inspect/change/remove and persistence tasks under [item 19](../inprogress/core-musicxml-write-assessment.md). This proposal does not credit rendering as an authoring route. Exact >7 accidental spelling and unspecified fractional-key glyph choices are recorded as unresolved in the assessment, not silently selected by this item.
